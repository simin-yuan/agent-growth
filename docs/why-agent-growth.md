# 我们为什么做 agent-growth：AI 记忆需要一个 Git

> 给 AI 的记忆配了个账本、红绿灯和后悔药。

## 一、所有 AI 都在做记忆，但没人做记忆治理

2026 年，几乎每个 AI 产品都在说「我们有记忆了」。但你把「记住」和「可信地变好」分开看，会发现一个巨大的空白：

- 它会记住你上次说的话，但**记错了你也不知道**。
- 它会「学习」你的纠正，但**学歪了你也不知道**。
- 两条纠正互相矛盾，它**默默选了其中一条，不告诉你为什么**。
- 你想回到上周的行为，**没有任何办法**。

这不是成长，这是漂移。

我们把这层缺失叫**记忆治理**：不是「存什么」，而是「谁改的、为什么改、改错了能不能退」。`agent-growth` 就是补这一层。

## 二、记忆 ≠ 成长

一个只会堆积事实的系统，不是在学习，是在膨胀。

真正的成长，第一性原理拆开只有三步：

1. **从一次纠错里提炼出一条可复用的规则**（不是记住「你说了什么」，而是记住「以后该怎么做」）；
2. **新规则和旧规则冲突时，先隔离，不污染行为**；
3. **每一次变化都可追溯、可撤销**。

缺了第 2 步和第 3 步，前 1 步越多，系统越不可信。这就是为什么很多「自进化 Agent」越用越飘——它们只做了第 1 步。

## 三、三个机制，对应三个字：账、灯、药

**账本（Git）**：每条规则 = 一个 markdown 文件 = 一次 Git commit。谁、什么时候、因为哪次纠正加的，`git log` 一清二楚。

**红绿灯（冲突隔离）**：新规则入库前，先和现有规则比对。冲突的，标记 `status: conflict`，**绝不进入 prompt**，等你裁决 `keep-new / keep-old / keep-both`。

**后悔药（一键回滚）**：`growth rollback <id>` 就是 `git revert`。不需要自己写版本控制——Git 三十年前就把这件事做完了。

## 四、为什么是 Git，而不是向量库

因为问题不在「检索」，在「治理」。

向量库擅长「找相似」，但它回答不了三个问题：**谁改的、为什么改、怎么退。**

Git 天生回答这三个问题。我们只是把「AI 学到的规则」当成代码一样管理——这听起来朴素，但它是把「AI 记忆」从玩具变成工程系统的关键一步。

## 五、为什么零额外 API Key

在 Claude Code / Cursor 里，宿主模型本身就是顶级 LLM。让你再配一个 `GROWTH_LLM_KEY` 才能用记忆，是反人性的。

所以 MCP 模式下，宿主自己提炼规则（`rule`）、自己比对冲突（`conflicts_with`），传给 `growth_learn`。**零 key、零额外 token、30 秒开箱即用。** 独立 CLI / 离线模式仍然可用，配 key 只是可选项。

## 六、它和「光之涌现」的关系

光之涌现的定位是「**可信的智能体，会成长的 AI**」。

`agent-growth` 就是这八个字的产品化：**可信** = 可审计、可回滚；**会成长** = 从纠错中沉淀规则。我们不想再讲一遍愿景，我们想先交出一个能装、能跑、能验证的小东西。
